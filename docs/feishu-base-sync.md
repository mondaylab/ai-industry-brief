# 行业动态同步到飞书多维表格

GitHub 的 `brief-data` 是发布数据源。同步只投影已公开的标题、刊发日期、栏目、公司或产品、主题、摘要、来源和两个阅读链接。不要在飞书改这些同步字段；请修改仓库中的原稿。论文、评测和架构选题不在这条同步链路内。

## 本地同步

需要 Node.js 22 和已授权的 `lark-cli`。目标表使用 `标题` 或空表自带的 `文本` 作为主字段，另建以下字段：

- 日期：`刊发日期`，采用北京时间。
- 单选：`栏目`，选项为 AI 产品前线、AI 行业现场、AI 资本与牌局、AI 能力底座。
- 文本：`公司或产品`、`主题`、`摘要`、`来源`、`来源日期`、`同步 ID`、`同步版本`。来源日期保留原始精度和注明的历史背景。
- URL：`报刊链接`、`原文链接`。

通过环境变量 `FEISHU_BASE_TOKEN` 和 `FEISHU_TABLE_ID` 指向目标表。默认读主仓库最近 30 个自然日的结构化刊期，不会把老刊或手动记录删掉：

```bash
npm run base:sync
npm run base:sync -- --apply --wait-for-pages
```

不带 `--apply` 时只读取并打印变动数量。发生超时或部分失败后重新做预检，不直接重放写入请求。同步 ID 由刊发日和规范化来源 URL 派生，与标题、栏目及顺序无关；源链接换成另一篇或另一个路径会产生新 ID，需人工确认旧记录。内容不变会跳过；若外部编辑了同步字段而没改同步版本，脚本不会把这种手工编辑当作源端变化。保留两列同步元数据，只从常用视图隐藏。

## GitHub Actions

工作流仅在 `main` 运行，默认关闭。先为独立的飞书自建应用授予目标表的字段读取和记录读写权限，再配置仓库 Variables：`FEISHU_BASE_TOKEN`、`FEISHU_TABLE_ID`、`FEISHU_BASE_SYNC_APP_ID`，以及 Secret：`FEISHU_BASE_SYNC_APP_SECRET`。不要把应用密码或个人授权令牌提交到仓库。

最后把 `FEISHU_BASE_SYNC_ENABLED` 设为 `true` 并手动触发一次，确认应用身份可访问指定表。此后 `main` 的日报数据变更会触发同步。工作流等待最新一期 JSON 在 GitHub Pages 生效，然后执行单向写入；它不修改公开共享设置。开启后，不要同时从本地对同一张表执行写入。
