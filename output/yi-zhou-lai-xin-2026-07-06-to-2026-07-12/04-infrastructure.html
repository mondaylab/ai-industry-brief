能力底座
AI Agent 要先可控

权限、评测、成本、上下文和可观测性，是 AI Agent 能不能进入企业系统的底层条件。

07.07prnewswire.com

ModelCop 发布 Agent 身份安全平台

ModelCop 发布 AI Agent 身份安全平台，用于发现 Agent 账号、分配权限并记录活动。企业账号管理的范围正在从员工扩展到数量不断增加的非人工身份。

07.07aws.amazon.com

Bedrock Guardrails 增加 Agent 安全检查

AWS 为 Bedrock Guardrails 增加执行过程检查，可在 Agent 多轮运行中拦截不合规输入和动作。安全护栏正从回答前后的一次检查，深入 Agent 的每一步执行。

07.07microsoft.com

Memora 提出 Agent 长期记忆方案

Microsoft Research 发布 Memora，让 Agent 压缩并保存长任务中的关键信息。长期记忆不仅决定 Agent 能否连续工作，也直接影响上下文成本。

07.10openai.com

OpenAI 发布 GPT-5.6 模型

OpenAI 发布 GPT-5.6，增强复杂推理、工具调用和搜索能力。模型升级的重点正在从单轮回答分数转向完整的 Agent 工作流。

07.10cloud.google.com

Google Cloud 发布 Cloud Run Sandboxes 预览

Google Cloud 发布 Cloud Run Sandboxes 预览，为 AI 生成代码和 Agent 任务提供隔离环境。Agent 想进入生产系统，首先需要一个出错时不会伤及业务的执行空间。

07.10aws.amazon.com

AWS 发布 MCP 工具设计实践

AWS 发布 MCP 工具设计指南，覆盖上下文、参数和错误响应等细节。Agent 能否稳定调用工具，越来越取决于工具本身是否为机器理解而设计。

07.12cloud.google.com

Google Cloud 提出 Agent 表现评估方法

Google Cloud 提出结合通过率、失败边界和任务难度评估 AI Agent。单一成功率已经不足以判断 Agent 是否可靠，评测开始转向解释它在哪些情况下会失败。

07.12aws.amazon.com

KTern.AI 用 Bedrock AgentCore 构建 SAP Agent

KTern.AI 使用 Bedrock AgentCore 构建 SAP 迁移与治理 Agent。Agent 正进入 SAP 这类复杂企业系统，开始承担过去高度依赖顾问的实施工作。
