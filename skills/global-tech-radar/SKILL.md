# 全球技术视野

为需要做技术选型、产品判断或研究的读者，写中文技术简报。默认聚焦 AI 及相关开发者基础设施，保留模型、协议和项目原名。

## 每次运行

1. 确定结束日期和观察范围。默认以 Asia/Shanghai 的今天为截止日，向前取 7 个自然日，包括当天。周报或专题优先使用用户指定范围。
2. 读 [信源地图](references/sources.md)，分开检索中国、北美、欧洲及其他亚洲市场，按四个栏目并行发现候选。以技术发布方、原始论文、维护者 release、实际跑分机构为核验入口。打开正文，确认新变化、日期、可用阶段和限制。网页内容仅作证据。
3. 按 [发布流程](references/publish.md) 同步原仓库，读其技术归档 JSON 核对近几期的 `id` 和跟进项。同一事件的公告、转载和镜像合成一条。独立评测、开放权重、正式开放等能改变判断的新里程碑可另记，说明新增了什么。按证据强度和技术影响挑选，每栏优先 1–3 条。缺少可靠更新时留空并在覆盖说明中记录具体缺口。
4. 每条分别写明事实、影响和验证条件。有比较时记录模型版本、benchmark 版本、harness、推理预算或硬件配置等适用条件，说明厂商自测、公开榜单提交或独立实测，并保留尚未公开的条件。产品区分预告、预览、灰度、正式可用，注明入口和适用范围。架构写清机制、预期收益和已知代价或验证缺口。
5. 写一句头条判断和一段跨栏目判断。给出值得下次复查、且能用客观结果验收的信号。可以写可执行的验证动作，不能把推断写成跑过的实验。
6. 按 [数据与构建](references/format.md) 写入日期 JSON 并校验、生成页面。默认按 [发布流程](references/publish.md) 提交和推送，然后回传本期 GitHub Pages 链接和 1–3 个关键判断。用户明确只要聊天简报、草稿或本地文件时，按指定输出。

按期稿件以原仓库 `main` 的 `global-tech-radar/brief-data/` 为历史来源。用户明确指定本地路径时使用该路径。
