# 小红书强弱信号风格参考

## Positioning

“强弱信号”的小红书文案要做两件事：

1. 让非技术读者愿意点开。
2. 让读者读完后觉得“这周 AI 行业大概发生了什么，我懂了”。

它不是论文摘要、行业研报、工具清单，也不是单纯介绍海报怎么做。

## Good Title Patterns

标题要有网感，但不能空。优先使用：

- `这周 AI 开始上班了`
- `这周，AI 终于开始接活了`
- `老板开始给 AI 算绩效了`
- `进公司后，它第一件事是被算账`
- `这周的 AI 新闻，有点像入职第一天`
- `终于轮到 AI 打工了`

可用结构：

- `这周 + 具体变化`
- `终于 + 变化`
- `老板/公司/打工人 + AI + 具体场景`
- `一句口语判断 + 具体行业信号`

避免：

- `AI 行业周报：...`
- `AI 行业动态汇总`
- `AI 正在重塑未来`
- `AI Agent 的商业化进程观察`
- `大模型基础设施迎来关键节点`

## Body Structure

推荐结构：

1. 开头一句给判断。
2. 用 3-5 个“这周信号”解释判断。
3. 每个信号最好带公司/产品/场景。
4. 结尾收束成一句普通人能记住的话。

Example outline:

```text
这周看 AI 新闻，有个感觉很明显：它开始像一个要被管理的员工了。

Notion 让第三方 Agent 进入工作区，GitHub 让 Copilot Agent 的执行过程可见，Sourcegraph 让 Agent 批量改代码。

这说明大家关心的重点变了：能不能回答已经不够了，能不能被分派、被检查、被追责，才是公司真正会买单的部分。

...
```

## Language Rules

- Use `AI Agent` / `Agent`; avoid `AI 代理`.
- Use `公司`, `老板`, `工作流`, `账本`, `权限`, `交付`, `上岗`, `接活` when they fit the facts.
- Use short sentences and line breaks.
- Keep one paragraph to 1-3 sentences.
- Do not overuse rhetorical questions.
- Do not write like a press release.
- Do not start every paragraph with `第一/第二/第三` unless the user wants a structured version.

## Hashtags

Default tags:

```text
#AI #AI工具 #AIAgent #AI行业 #AI周报 #强弱信号 #星期一研究室
```

Add context tags only when relevant:

- `#GitHubCopilot`
- `#Notion`
- `#Claude`
- `#职场效率`
- `#科技趋势`
